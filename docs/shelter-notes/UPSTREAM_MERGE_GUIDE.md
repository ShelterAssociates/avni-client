# Keeping the Shelter fork in step with upstream Avni — merge guide

_For `~/avni/avni-client`. Upstream: `https://github.com/avniproject/avni-client` (remote `upstream`). Shelter work lives on `shelter-master` as 26 commits, merged with upstream `3056a2145` on 2026-10-13. `master` is kept byte-identical to upstream and never receives Shelter commits._

Avni keeps developing the client; Shelter keeps a thin layer on top. This guide is written so that anyone — including someone who has never seen the GIS code — can bring in a new upstream release in an afternoon and know when they are done.

---

## 0. The principles that make merges cheap

1. **Shelter code lives in Shelter-only files.** Everything substantial is under `src/gis/`, `src/views/MapPickerScreen.js`, `src/views/gis/`, `src/service/GisSyncService.js`, `src/views/common/BrandLogos.js`, `test/gis/`, and the generic-flavour logo assets. Upstream never touches these; they merge without conflict. When you add a Shelter feature, put it there.
2. **Touch upstream files only with small, additive hooks.** Each hook is one import plus one call (or a few lines), placed next to something stable, and carries a `// Shelter Associates GIS:` or Shelter comment so it is recognisable in a conflict. Do not reformat, reorder or "improve" upstream code around the hook.
3. **Shared behaviour is called, not copied.** E.g. Register page and the map popup both call `registrationChoices()`; the map header is Avni's `AppHeader`. If upstream changes those, we inherit the change instead of diverging.
4. **Never edit generated or environment files into the fork**: `src/framework/Config.js` (generated by `make as_*`), `Config.js`'s GIS values, keystores, `autolinking.json`.
5. **Tests are the merge safety net**: `npx jest test/gis` must be green after every merge; the map must be opened once on a device.

## 2. Merge procedure

Use **merge**, not rebase: Shelter's history is already shared (commits are the audit trail in the built APKs' `COMMIT_ID`), and a merge keeps each Shelter commit intact.

### 2.1 Prepare
```bash
cd ~/avni/avni-client
git status                      # must be clean; commit or stash first
git fetch upstream --tags
git log --oneline -1 upstream/master
git tag shelter-pre-merge-$(date +%Y%m%d)      # easy way back
```
Decide what to merge: upstream `master`, or a release branch/tag (e.g. `18.1`). Avni releases from branches like `17.3`, `18.0`; check what production Avni server version Shelter uses (Menu → About / server `/api/version`) and merge the matching client release — the client and server versions must be compatible.

### 2.2 Merge
```bash
git merge --no-ff upstream/<branch-or-tag>
```
Expect conflicts only in files from §1. For each:
- open the file, find the `<<<<<<<` blocks;
- keep upstream's version of everything that is not a Shelter hook;
- re-insert the Shelter hook exactly as described in §1 (search the file for `Shelter` — the comments mark the spots; if the marker is missing the hook is gone);
- `git add` the file.

Special cases:
- **`package-lock.json`**: `git checkout --theirs packages/openchs-android/package-lock.json` (upstream's), then after the merge `cd packages/openchs-android && npm install --legacy-peer-deps` — this re-adds `@turf/turf` and `leaflet` to the lock. Do not attempt to resolve lockfile hunks by hand. `yarn.lock`: keep upstream's; do not let `npm` rewrite it (if it does, `git checkout -- yarn.lock`).
- **`Config.js`** is not tracked; nothing to merge. Regenerate with `make as_*` after the merge.
- **Translations**: JSON conflicts are usually adjacent additions; keep both sides, check the file still parses (`python3 -c "import json;json.load(open('translations/en.json'))"`).
- **Deleted-by-them / modified-by-us**: if upstream deleted a file we hooked (e.g. replaced `RegisterView.js`), find upstream's replacement and re-apply the hook's *intent* from §1 there.

### 2.3 Re-verify the hooks even where git reported no conflict
Git merges cleanly when the changes are in different lines — which is exactly how a hook silently stops being called (upstream adds a new code path that bypasses it). After the merge:
```bash
cd packages/openchs-android
grep -n "Shelter" src/views/SyncComponent.js src/action/subject/SubjectRegisterActions.js src/views/RegisterView.js src/views/common/AppHeader.js
grep -n "mapStructure" src/utility/CHSNavigator.js src/views/subject/SubjectRegisterView.js src/state/SubjectRegistrationState.js
grep -n "GisSyncService" src/service/AllServices.js
grep -n "MapPickerScreen" src/views/index.js
grep -n "gis_config" ../../Makefile
grep -n "copyLeafletAssets" android/app/build.gradle
```
Each must hit. Then read the surrounding code once: is the hook still on the path that runs? (E.g. did upstream add a second save path in `SubjectRegisterActions` that also needs `recordStructureMapping`?)

### 2.4 Build and test
```bash
cd ~/avni/avni-client/packages/openchs-android
npm install --legacy-peer-deps
npm run prebuild:android               # autolinking.json — stale copies are the classic "TurboModuleRegistry … could not be found" crash
npx jest test/gis                      # all green
cd ../.. && make test                  # upstream's suite, as far as it runs on this machine
GIS_SERVER_URL=http://localhost:8000 GIS_API_KEY=<local key> make as_prod_dev flavor=generic   # or the env you test against
cd packages/openchs-android && npx react-native run-android --mode=genericDebug
```
Device checklist (5 minutes):
1. Start-up page and login show Avni × Shelter logos; header shows the Shelter mark.
2. Sync completes; sync screen shows "Downloading map n/m: …"; logcat has `GIS saved for … structures, boundary yes`.
3. Register → subject type → "Opening map…" → map with boundary + houses; tap empty house → Use this → form has the house number pre-filled → save → logcat `Structure mappings: sent 1` on next sync.
4. Home button and Menu → Slum map → popup → map; tap registered house → card → View household → Back returns to map.
5. Colour by a filter; tick/untick legend swatches; House numbers checkbox; search a number.
6. Airplane mode → reopen map → polygons still draw.
7. `adb logcat | grep -E "CONSOLE|Uncaught|FATAL"` shows nothing during the above.

### 2.5 Finish
```bash
git commit                              # the merge commit; message: "Merge upstream avni-client <version>"
git log --oneline upstream/<ref>..master  # Shelter commits still on top
```
Push only when asked; build a release with a **higher `versionCode`**.

## 3. Watch-list: upstream changes that break Shelter silently

| If upstream… | Then Shelter must… |
|---|---|
| Changes how `Config.js` is generated (`_create_config`) | Re-append `$(gis_config)`; check `GisConfig.isConfigured()` is true in a debug build (map button visible). |
| Changes the sync flow (`SyncComponent`, new sync service) | Move the `GisSyncService.syncGisData` call to the new "sync finished OK" point. |
| Changes registration actions/work lists (`RegisterView`, `WorkList`, `WorkLists`) | Update `registrationChoices`/`workListsFor` in `src/gis/mapBrowser.js`; the Register page must show the same buttons as upstream's version would. |
| Changes `SubjectRegisterActions.onLoad/onSave` or `SubjectRegistrationState.clone` | Re-place the four `mapStructure` touches and `recordStructureMapping`. Test: register from the map → house number pre-filled → mapping sent. |
| Changes `AppHeader` layout/props | Re-place `renderBrand()`; keep `hideIcon` semantics for the map screen header. |
| Renames `LandingView.layoutConstants.bottomBarHeight` or the home-tab render | Fix `mapButtonStyle` / `{home && this.renderMapButton()}`. |
| Upgrades React Native / Hermes | Re-run the map: the page must not rely on `fn.toString()` (already avoided); check `react-native-webview` props `allowFileAccess*` still exist; check `react-native-dropdown-picker` still renders over the WebView. |
| Upgrades Realm or `openchs-models` | Run `npx jest test/gis`; check `Individual.enrolments/encounters`, `getValueWrapper`, `Concept.dataType.Coded` still exist (used by `observationAnswers.js`). |
| Changes the flavour assets layout (`android/app/src/generic/assets`) | Move `shelter-logo*.png` with `logo.png`. |
| Changes Gradle/AGP | `copyLeafletAssets` uses `layout.buildDirectory` and `preBuild` — both long-stable; if the build breaks here, read Gradle's message; the goal is simply "leaflet.js + leaflet.css inside `assets/leaflet/`". Verify with `unzip -l <apk> | grep leaflet`. |
| Adds a native module | `npm run prebuild:android` before building (this fork's autolinking is a manual step — `android/rn-modules.gradle`). |

## 4. Rules for new Shelter work (so the next merge stays cheap)

- New logic → new file under `src/gis/` (pure, unit-tested) or `src/views/gis/`.
- Upstream file needed? Add **one** hook: an import and a call, with a `// Shelter Associates …` comment stating *why*. Never edit surrounding lines.
- Don't fork a copy of an upstream component; wrap or call it (`AppHeader`, `DropDownPicker`, `MenuView.Item`, `registrableSubjectTypes` pattern).
- Commit messages: `gis: <what changed, why>` for map work; plain descriptive messages otherwise; no co-author trailers.
- Add the file to §1 of this guide when you touch a new upstream file. Keep this document next to the code that it describes.
